# moq-dev spike: one MoQ object between a browser and Rust

Phase 0 validation code, not application structure. It sends one object through a local `moq-relay` and checks that the receiver got the same bytes. Results are recorded in [docs/experiments/2026-10-10-moq-dev-object-transfer.md](../../docs/experiments/2026-10-10-moq-dev-object-transfer.md).

## Pinned versions

| Part | Version | Pinned by |
|---|---|---|
| `moq-relay` | 0.17.2, prebuilt release binary | `scripts/fetch-relay.sh` (SHA-256 checked) |
| `moq-net` | 0.3.10 | `rust-client/Cargo.toml`, `Cargo.lock` |
| `moq-tokio` | 0.19.23 | `rust-client/Cargo.toml`, `Cargo.lock` |
| `@moq/net` | 0.4.2 | `web/package.json`, `bun.lock` |
| `playwright-core` | 1.64.0 | `web/package.json`, `bun.lock` |

The relay is a prebuilt binary because `moq-relay` 0.17.2 declares `rust-version = 1.95`. The Rust client builds with 1.91 or newer.

## Prerequisites

- Rust 1.91 or newer, Bun, `curl`, `perl`
- A Chromium or Chrome binary, version 143 or newer (the `protocols` WebTransport option). Its path goes in `CHROMIUM_PATH`. Playwright's browser download is not used.

## Setup

```bash
cd spikes/moq-dev
bash scripts/fetch-relay.sh
cargo build --manifest-path rust-client/Cargo.toml
bun install --cwd web --frozen-lockfile
export CHROMIUM_PATH="/path/to/chromium"
```

## Run

Terminal 1, the relay on `127.0.0.1:4443`:

```bash
bash scripts/relay.sh                     # accepts every version it supports
bash scripts/relay.sh moq-transport-22    # accepts only this version
```

Terminal 2, one transfer:

```bash
bash scripts/transfer.sh b2r demo                     # browser publishes, Rust subscribes, default offer
bash scripts/transfer.sh b2r demo moq-transport-22    # both clients pinned
bash scripts/transfer.sh r2b demo moq-lite-06         # Rust publishes, browser subscribes
bash scripts/transfer.sh b2b demo                     # browser to browser
LIVE_INTERVAL_MS=500 bash scripts/transfer.sh b2b demo   # browser publisher keeps writing new groups
```

The script prints both logs and exits 0 only if the subscriber received the exact payload. The payload is random per run. `MATCH` (Rust) or `[spike] match` (browser) marks success.

Repeated runs across versions, each with its own relay:

```bash
bash scripts/matrix.sh 4 moq-lite-06 moq-transport-20 moq-transport-18 moq-transport-16
```

## How a version is pinned

| Side | Setting |
|---|---|
| Relay | `--listen-version moq-transport-22` |
| Rust client | `--connect-version moq-transport-22` (from `moq_tokio::connect::Config`) |
| Browser | `webtransport: { protocols: ["moqt-22"] }` passed to `Moq.Connection.connect` |

The browser pins by WebTransport subprotocol: `moqt-NN` for MOQT drafts 15 and later, `moq-lite-NN` for moq-lite 03 and later.

## Provisional settings

These exist only to make the local run possible. None is a project decision.

- Anonymous publish and subscribe on every path (`--auth-public "**"`).
- A self-signed certificate generated by the relay at start. Both clients fetch its SHA-256 from `http://127.0.0.1:4443/certificate.sha256` over plain HTTP and pin it.
- The WebSocket fallback is disabled on both clients so that only WebTransport over QUIC is exercised.
- Relay log level `debug`; logs are written to `logs/` and not kept in version control.
