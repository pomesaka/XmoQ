# Interop peers for FETCH / LOC / MSF on MOQT draft 18

All sources were fetched on 2026-10-10 (every row below has that read date). Nothing was built or run. "Code" means I read the identifier in the repository at the named commit; "README" means only a document says so. Shallow clones used for reading are under `scratchpad/repos/`, draft texts under `scratchpad/specs/`.

URL prefixes used below:

- `MT@tag` = `https://github.com/moqtail/moqtail/blob/dd8623dacd/` (tags `relay@0.15.0`, `moqtail-rs@0.15.0`, `moqtail@0.13.0`, all on commit `dd8623dacd`)

## Headline findings

1. **The specs do not line up on draft 18.** `draft-ietf-moq-loc-04` cites `draft-ietf-moq-transport-19`, not 18. `draft-ietf-moq-msf-01` cites transport-18 and `draft-ietf-moq-loc-02`. LOC-02 puts TIMESTAMP at `0x06`, which draft 18 assigns to `SUBGROUP_DELIVERY_TIMEOUT` with Track scope only. LOC-04 moved TIMESTAMP to `0x10` and VIDEO_FRAME_MARKING to `0x09`. Implementations that run "draft 18 + LOC-04 + MSF-01" exist (see 3), so the combination is used in practice, but it is a combination no single spec revision names.
2. **moqtail is not a LOC-04 or MSF/LOC peer.** At the versions XmoQ uses, moqtail carries the pre-04 LOC property ids (`Timestamp = 0x06`, `VideoFrameMarking = 0x0A`), its catalog model is CMSF (`packaging: 'cmaf' | 'chunk-per-object' | 'timeline'`, no `loc`), and its demo apps use CMAF. It does implement FETCH and Joining FETCH on draft 18, with a relay cache. `main` has moved to `moqt-22`; draft 18 lives on the `draft-18` branch and the released tags.
3. **Peers that implement draft 18 + Joining FETCH + LOC-04 ids + MSF-01 catalog exist:** `Eyevinn/moqlivemock` (Go: publisher, subscriber, relay with cache; draft 18 only), `Eyevinn/warp-player` (browser, draft 18 only), `openmoq/moq-playa` (TypeScript, browser; git main only, the npm release is older), `gmarzot/aiomoqt` (Python), `meetecho/imquic` (C). `facebookexperimental/moxygen` gives a draft-18 relay with cache, FETCH and Joining FETCH, but its media format is CMSF/moq-mi, not LOC.
4. **The shared interop runner does not test FETCH, LOC or catalogs.** The only cross-implementation FETCH / Joining FETCH results I found are moxygen's conformance script as reported on the moq-wg wiki for the 2026-09 virtual hackathon: only moxygen passes the FETCH sections, and even moxygen fails "Joining FETCH" in the posted run.

### MSF-01 text that drives the FETCH requirement

| Point | Verbatim | Source |
|---|---|---|
| Catalog needs Joining FETCH | "Subscribers accessing the catalog MUST use SUBSCRIBE with a Joining FETCH (offset = 0) in order to obtain the latest complete catalog along with all subsequent catalog objects, including delta updates, that follow." | `IETF`draft-ietf-moq-msf-01.txt l.530-533 |
| Catalog track name | "The catalog track MUST have a case-sensitive Track Name of "catalog"." | same, l.509 |
| Version string | "For usage against IETF Internet-Draft releases, follow the convention of specifying the version as "draft-XX"." But every example in the draft uses `"version": "1"` (l.1686, 1728, 1833, ...). The draft is inconsistent with itself; implementations accept both (see below). | same, l.595-597 |
| Packaging | `"packaging": "loc"` in all examples; Table 3 lists `loc` | same, l.859, 1692 |

Note that Joining FETCH was removed from the transport after draft 19: shiguredo/moqt-js `CHANGES.md` l.935 "[CHANGE] FETCH メッセージを draft-20 のワイヤ形式に変更し Joining FETCH を削除する"; moq-playa README l.380 "Draft 22 has no Joining FETCH". So MSF-01's catalog rule only works literally on drafts up to 19.

Consequences for XmoQ, stated as facts rather than a recommendation:

- XmoQ is not limited to testing against itself. For LOC-04 + MSF-01 + Joining FETCH on draft 18, moqlivemock (native), warp-player and moq-playa (browser) implement the same combination.
- Keeping moqtail as the only peer covers FETCH and Joining FETCH at the transport level, and nothing of LOC-04 or an MSF catalog with `packaging: "loc"`.
- The id choice matters: `0x10` Timestamp and `0x09` Video Frame Marking (LOC-04) versus moqtail's `0x06` and `0x0A`. Under draft 18's registry an Object property `0x06` is out of scope.
- The MSF catalog `version` value is ambiguous in the draft ("draft-XX" in text, "1" in examples). moqlivemock, moxygen, aiomoqt, imquic and moqtail emit `"draft-01"`; warp-player and moq-playa accept both.
- draft 18 is still the common interop target (2026-09 hackathon), but the transport is at draft 22 and moqtail main, shiguredo and moq-playa are moving there; Joining FETCH does not exist from draft 20.
