# Requirements and status

**Discussed** means explicitly raised in planning; **proposed** means suggested but not confirmed; **decided** means confirmed by the project owner and not yet implemented; **implemented** means the code is in `main` and a recorded run in `docs/experiments/` exercised it; **validation required** means not proven.

| Requirement | Status |
| --- | --- |
| Own MoQ Transport implementation in Rust and TypeScript, pinned to draft 18 | Implemented for the Phase 0b scope: the codec and session in Rust and TypeScript, a client in each, and a minimal relay in Rust that routes by track and by announced namespace and takes one track from up to 4 publishers. One Object passes between every pairing of own and `moqtail` clients through either relay. The parts of the draft that are not implemented are listed in [implementation notes](moqt-implementation-notes.md) |
| One-to-many live broadcast | Implemented on loopback: a page's video and audio reach several viewers through the relay (`mise run demo`), and one video track reached 1,000 viewers of the Rust client on one Mac ([record](experiments/2026-10-11-one-video-track-to-many-viewers.md)). Validation required over real links |
| Browser publishing and viewing | Implemented for Phase 1: Chromium (Chrome, Edge) on desktop, on loopback, in the demo, with audio added. The demo also ran in Playwright's Firefox ([record](experiments/2026-10-11-demo-in-firefox-and-webkit.md)). Which other browsers are supported is undecided |
| WebCodecs and MoQ/WebTransport | Implemented in Chromium on one machine: H.264 and Opus of WebCodecs over the own MoQ Transport. Validation required on real links and in Safari |
| Media packaged as LOC, tracks described by an MSF catalog (`draft-ietf-moq-msf-01`), with the FETCH that needs | The MSF catalog is implemented: `@xmoq/msf` reads, follows and publishes a catalog track, run against `moqlivemock` in both directions; delta updates and GZIP are not. Media in LOC: the timing properties and the H.264 payload of `draft-ietf-moq-loc-04` on draft 18 are implemented in `@xmoq/loc` (the revision decided on 2026-10-11), and `@xmoq/media` receives, sends, publishes and plays a video track with them, a Group on one stream (decided on 2026-10-11); a page played the video of `moqlivemock`'s publisher, and a page encodes video in a browser that another page plays through the relay; the demo's page draws the frames (`demo/`, not a package). A relay cache of the latest Group of a track is implemented for a track that has a publisher, with the bounds decided on 2026-10-11 (8 MiB and 4,096 Objects a track, 256 MiB in all); keeping it for 30 seconds after the last publisher has gone is decided and not implemented. What is provisional is in the [open decisions](open-questions.md) |
| Audio | Implemented in its smallest form: Opus, mono, page to page through the relay and in the demo, played by the clock of the picture after one buffer (`createPlayout`). What was measured and what was not is in [the A/V demo and its limits](av-demo.md). A person found the sound smooth on 2026-10-12. Validation required: the sync was not judged by eye and ear |
| Rust relay and Rust CLI | The relay is implemented as the rows above say. A CLI is not: there is the one-shot client and scripts in `spikes/` |
| Ghostty video, audio, chat | Validation required: spikes wrote a broadcast as Kitty graphics and played its sound, with no terminal ([record](experiments/2026-10-11-a-broadcast-in-a-terminal-picture-and-sound.md)); a later spike plays both by one clock, joins the room and shows and sends its chat ([record](experiments/2026-10-12-the-terminal-viewer-joins-a-room.md)), and a person saw its picture in Ghostty on 2026-10-12. Not a part of the product yet |
| Durable Objects for room/chat state | Validation required: a room that says where a broadcast is, chat and a count ran in Miniflare on one machine, with the demo's pages; the publishing page registers with the room (decided 2026-10-11). Not on Cloudflare, no authentication |
| SNS event integration | Future goal |
| Multiple publishers / bidirectional calls | Future possibility |
| Reactions | Proposed; delivery undecided |
| Video codec | Decided for Phase 1: H.264 in Annex B format. Profile, level and key frame interval are undecided ([open decisions](open-questions.md)) |
| Latency, capacity | Undecided. Measured on one machine ([summary](av-demo.md)): [delay](experiments/2026-10-11-where-the-delay-of-the-demo-comes-from.md), [delay and loss](experiments/2026-10-12-video-over-a-link-that-delays-and-loses.md), [viewers](experiments/2026-10-11-one-video-track-to-many-viewers.md) |
| Authentication, privacy, recording | A token of the room that the relay checks is decided and implemented ([record](experiments/2026-10-11-authorization-tokens-of-a-room-checked-by-the-relay.md)); who may get one is undecided, as are privacy and recording |
| License and contribution policy | Undecided |

No user-facing CLI or installation steps are implemented yet. `xmoq-moqt-client` is a one-shot client for interop runs, not the terminal viewer.
