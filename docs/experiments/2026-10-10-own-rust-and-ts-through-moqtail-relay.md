# Own Rust and TypeScript MOQT clients through the moqtail relay (draft 18)

- Date: 2026-10-10
- Commit SHA: the commit that adds `interop/matrix.ts` together with this record. The runs were made on its working copy on top of `1841905`
- Roadmap item: Phase 0b, "One interop runner for every pairing (`interop/`), including the own Rust client, and a CI job that runs it"

## Objective

Connect the two own MoQ Transport implementations to each other for the first time: the Rust client (`crates/moqt-client` on `xmoq-moqt`) and the browser client (`interop/page.ts` on `@xmoq/moqt`), with the moqtail relay between them, in both directions. Until now each had only met moqtail peers. Run every other pairing from the same entry point, and see a subscription end with PUBLISH_DONE in both own subscribers.

Names used below: **own-browser** is `interop/page.ts`, **own-rust** is `xmoq-moqt-client`, **moqtail-browser** is `interop/peers/moqtail/browser/page.ts` on the `moqtail` npm package, and **moqtail-rust** is `interop/peers/moqtail/rust-client` on the `moqtail` crate.

## Commands

From the repository root:

```sh
mise run interop
mise run check
```

`mise run interop` (`scripts/ci/interop.sh`) builds the relay, both Rust clients and the pages, installs the Chromium of the pinned `playwright-core`, and runs `interop/matrix.ts`. The matrix starts `interop/run.ts` once per pairing, one after the other, each on its own port from 44400.

Two pairings were also run by hand with `--verbose`, which makes own-rust print the bytes of every stream (`--trace`). From `interop/`:

```sh
bun run.ts --publisher own-browser --subscriber own-rust    --await-publish-done --verbose --port 44401
bun run.ts --publisher own-rust    --subscriber own-browser --await-publish-done --verbose --port 44402
```

That a failing pairing fails the matrix was checked with a relay name that does not exist, and that a pairing over its time limit does, with a limit no pairing can meet:

```sh
bun matrix.ts --relay nosuch --only "own-rust to own-rust"
bun matrix.ts --only "own-browser to own-rust" --pairing-timeout-seconds 0.3
```

## Observed results

### Every pairing

All 14 pairings ended as expected. This is the table `matrix.ts` printed in the run of `mise run interop`:

| Pairing (relay: moqtail) | Result | Seconds |
|---|---|---|
| own-browser to own-browser, then PUBLISH_DONE | the payload matched | 1.1 |
| own-browser to own-rust, then PUBLISH_DONE | the payload matched | 0.9 |
| own-browser to moqtail-browser | the payload matched | 0.7 |
| own-browser to moqtail-rust | the payload matched | 0.8 |
| own-rust to own-browser, then PUBLISH_DONE | the payload matched | 0.6 |
| own-rust to own-rust, then PUBLISH_DONE | the payload matched | 0.2 |
| own-rust to moqtail-browser | the payload matched | 0.6 |
| own-rust to moqtail-rust | the payload matched | 0.2 |
| moqtail-browser to own-browser, then PUBLISH_DONE | the payload matched | 0.7 |
| moqtail-browser to own-rust, then PUBLISH_DONE | the payload matched | 0.6 |
| moqtail-rust to own-browser, then PUBLISH_DONE | the payload matched | 0.6 |
| moqtail-rust to own-rust, then PUBLISH_DONE | the payload matched | 0.2 |
| own-browser subscribes to a track nobody published | failed as expected (RequestFailedError: REQUEST_ERROR 0x10) | 0.6 |
| own-rust subscribes to a track nobody published | failed as expected (SUBSCRIBE rejected: error_code=0x10) | 0.2 |

"then PUBLISH_DONE" means that after the transfer the driver made the publisher leave and waited until the subscriber reported a subscription ended by PUBLISH_DONE. It is done wherever the subscriber is an own client; the moqtail clients do not report how a subscription ended. The two last rows expect the failure: the relay answers REQUEST_ERROR DOES_NOT_EXIST (`0x10`), and the row passes only if the log shows that code.

With everything built, `mise run interop` took 8 seconds. Building the relay from nothing took 33 seconds on this host (`cargo install`, measured once, into a scratch directory).

The check with `--relay nosuch` printed `FAIL own-rust to own-rust, then PUBLISH_DONE (0.1s): [driver] FAILED unknown relay nosuch` and exited 1. The check with the limit of 0.3 seconds printed `FAIL own-browser to own-rust, then PUBLISH_DONE (0.3s): stopped after the limit of 0.3s`, exited 1, and left no relay or client running.

### The two own implementations against each other

Both directions passed on the first run. No difference in how the two read the draft showed up.

What the two sent, from the `--verbose` runs:

| Bytes | own-browser | own-rust |
|---|---|---|
| SETUP | `af 00 00 11 07 0f` + `xmoq-moqt/0.0.0` | `af 00 00 18 07 16` + `xmoq-moqt-client/0.0.0` |
| PUBLISH_NAMESPACE | `06 00 0f 00 02 04 78 6d 6f 71 06 70 68 61 73 65 30 00` | the same 18 bytes |
| PUBLISH | `1d 00 19 02 02 04 78 6d 6f 71 06 70 68 61 73 65 30 06 6f 62 6a 65 63 74 01 01 10 01` | the same 28 bytes |
| SUBSCRIBE | `03 00 1f 00 02 04 78 6d 6f 71 06 70 68 61 73 65 30 06 6f 62 6a 65 63 74 04 10 01 10 80 01 01 02 01 01` | the same 34 bytes |
| PUBLISH_DONE | `0b 00 03 02 01 00` | the same 6 bytes |
| SUBGROUP_HEADER as the subscriber received it | `5c 00 00 00 00` (Subgroup ID field present) | `58 00 00 00` (Subgroup ID 0 by mode) |

The control messages are equal byte for byte where their content is equal. The two write the Subgroup Header differently for the same Subgroup ID 0, both forms being allowed by §11.4.2, and each decoded the other's form: own-rust printed `OBJECT group=0 object=0 status=Normal payload_len=54` for the `5c` stream, and own-browser delivered the Object of the `58` stream. The header own-rust wrote is known here only as the relay forwarded it; `--trace` printed no line for the stream own-rust wrote.

### PUBLISH_DONE

Both own publishers end their Track with `0b 00 03 02 01 00` (TRACK_ENDED, Stream Count 1, no reason). The relay logged `Received PublishDone message for request ID: 2 with status: TrackEnded` and `all 1 streams finished`, and then sent its own PUBLISH_DONE to the subscriber, `0b 00 19 02 01 16` + `Publisher disconnected`. The subscriber gets the same bytes when a moqtail publisher closes its session without a PUBLISH_DONE.

- own-browser resolved `Subscription.ended` with `{"type":"publish-done","statusCode":"2","errorReason":"Publisher disconnected"}`.
- own-rust printed `PUBLISH_DONE status_code=0x2 stream_count=1 reason="Publisher disconnected"` and `SUBSCRIPTION_ENDED why=PUBLISH_DONE, all streams closed received=1 wanted=2`.

### Shared fixtures

The TypeScript tests now read the 17 files of `fixtures/moqt-18/` that the Rust tests read, in place of byte strings of their own. Five of the files had been read by the Rust tests only (SUBSCRIBE_OK with LARGEST_OBJECT, and four subgroup streams, two of them with Object ID gaps); the TypeScript codec decoded all five to the values listed in the fixtures README and encoded those values back to the same bytes, with no change to the code. One test compares the files of the directory with the files the tests read, so that a file nothing reads fails the run; it failed when a `.hex` file was added to the directory for a moment. `mise run check` ran 291 TypeScript tests.

## Limitations and blockers

- **Not run on GitHub.** The CI job was written and passes `actionlint`, but no workflow run had happened when this record was written. Its caches, the Chromium download with `--with-deps` and its run time on a hosted runner are unverified.
- **The pairings run only locally on macOS so far**, with debug builds.
- **One Object per run.** Several Objects, several Groups, a slow subscriber and a publisher that leaves while Objects are in flight are not covered by any pairing.
- **The relay rewrites PUBLISH_DONE.** The reason and the Stream Count the subscriber sees are the relay's, so these runs do not show that a publisher's own reason or count reaches a subscriber.
- **No own relay.** `--relay` accepts `moqtail` only. The table of relays in `run.ts` has one row.
- **A run between two moqtail peers is refused**, as before: it would check nothing of this repository.
- The two byte fixtures the TypeScript tests used to carry on their own (subgroup streams of another capture, with headers `5d` and `58`) were dropped instead of being added to `fixtures/moqt-18/`: the shared files `subgroup-stream-from-moqtail-rs` and `subgroup-stream-from-moqtail-ts` have the same header types and field values and differ only in the payload text.
